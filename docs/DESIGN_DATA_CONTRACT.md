# 标证通设计数据契约

## 1. 目的

本契约解决后端模型、API 载荷、前端类型、演示夹具和 Figma 母版之间的字段、状态与文案漂移。目标不是让五层使用同一组字段名，而是让每个界面状态都能追溯到同一个业务含义，并且在数据缺失或未知时不猜测、不静默补造。

## 2. 单向事实链

| 层级 | 责任 | 允许做什么 | 禁止做什么 |
| --- | --- | --- | --- |
| 后端领域模型与确定性规则 | 保存事实、状态键、数值与审计记录 | 定义业务枚举、门禁和计算结果 | 为了配合界面文案改写业务含义 |
| API / Pydantic Schema | 传输稳定、可验证的载荷 | 使用明确字段和空值 | 混入视觉颜色、中文标签或演示值 |
| 前端 Adapter | 唯一兼容边界 | 接受已登记的 snake_case / camelCase 别名，输出单一 ViewModel | 在组件内重复转换、根据颜色或文案推断业务状态 |
| UI ViewModel | 为组件提供稳定字段 | 分离 `key`、`label`、`tone`、`source` 和操作权限 | 覆盖后端事实或替代人工结论 |
| Figma 母版 | 表达布局、组件状态和交互 | 使用 ViewModel 字段名与确定性样例 | 发明后端不存在的状态、结论、人数或金额 |

冲突优先级为：领域事实与确定性规则 → API Schema → 前端 Adapter → UI ViewModel → Figma 样例。视觉文案和视觉色调不参与业务计算。

## 3. 状态映射原则

业务键必须稳定，界面标签可以优化。任何组件都不得直接把后端枚举展示给用户。

### 3.1 风险与严重度

| 业务键 | 界面标签 | 视觉语义 | 使用说明 |
| --- | --- | --- | --- |
| `fatal` | 阻断项 | `danger` | 会阻止就绪或交付；禁止使用“致命” |
| `high` | 高风险 | `warning` | 需要优先处理，但不等于 Run 失败 |
| `medium` | 待复核 | `review` | 需要确认、补充或判断 |
| `low` | 一般 | `neutral` | 非阻断的普通问题 |
| `info` | 信息 | `neutral` | 只读结果或说明 |

### 3.2 Agent Run

| 业务键 | 界面标签 |
| --- | --- |
| `queued` | 排队中 |
| `planning` | 正在规划 |
| `running` | 运行中 |
| `waiting_approval` | 等待人工确认 |
| `completed` | 已完成 |
| `failed` | 运行失败 |
| `cancelled` | 已取消 |

“存在阻断项”不是 Run 状态。阻断由输出严重度和 Step 的 `blocked` 状态表达。

### 3.3 Agent Step

| 业务键 | 界面标签 |
| --- | --- |
| `pending` | 未开始 |
| `running` | 执行中 |
| `waiting_approval` | 等待人工确认 |
| `completed` | 已完成 |
| `failed` | 执行失败 |
| `blocked` | 前置条件未满足 |
| `cancelled` | 已取消 |

### 3.4 人工确认

| 业务键 | 界面标签 |
| --- | --- |
| `pending` | 待处理 |
| `approved` | 已同意 |
| `rejected` | 已退回 |
| `cancelled` | 已取消 |

未知审批类型统一映射为 `unknown`，界面显示“未知审批类型”，不得伪装成合规覆盖或其他高权限操作。

### 3.5 来源复核

| 业务键 | 界面标签 | 说明 |
| --- | --- | --- |
| `verified` | 已核验 | 人工已确认来源与内容 |
| `manual_review` | 待人工复核 | 模型候选或置信度低于阈值 |
| `rule_result` | 规则结果 | 确定性规则产生，置信度不适用 |

置信度不是准确率。小于 `0.70` 的候选必须进入 `manual_review`，不得用绿色或“通过”弱化该状态。

## 4. 缺失、未知与失败

| 情况 | 统一处理 |
| --- | --- |
| API 请求失败 | `source=failure`、`data=null`，显示可重试错误；禁止静默回退演示数据 |
| API 返回空集合 | 视为合法空状态，不填入演示记录 |
| 未知枚举 | 保留原始值用于日志，ViewModel 使用 `unknown` 或人工复核状态；禁止就近猜测 |
| 来源文档缺失 | 显示“未提供来源文档”，相关结论不可进入已核验状态 |
| 来源页码缺失 | 显示“页码未提供”，不得显示第 0 页 |
| 摘录缺失 | 显示“未提供来源摘录”，不得用摘要冒充原文 |
| 置信度缺失 | 显示“置信度不适用”或“待确认”，不得默认为 0 或 100% |
| 日期、金额、数量 | 由后端或确定性纯函数计算；前端仅格式化显示 |
| 演示模式 | 只有显式启用时使用确定性夹具，并标记 `source=demo` |

## 5. Figma 与代码的对齐方式

1. Figma 组件属性使用 ViewModel 语义，例如 `State=WaitingApproval`、`Tone=Review`，不直接绑定后端中文文案。
2. 每个业务组件使用确定性样例 ID，例如 `RUN-20260719-001`、`REQ-013`，样例值来自 `demo/` 或前端已验证夹具。
3. 组件说明同时记录业务键、显示标签、空状态和不可用状态；颜色只作为辅助，不是唯一状态线索。
4. Figma 中的组件变体是视觉状态，不等于新增领域枚举。`Tone=Warning` 只能由中央映射表产生。
5. React 实现开始前，再建立 Figma Code Connect；没有用户确认的母版不进入代码映射。

## 6. 漂移检查

后续实现应增加以下自动检查：

- 后端 Schema 枚举与前端 ViewModel 枚举覆盖测试；
- snake_case / camelCase 只在 Adapter 测试中兼容；
- 每个未知枚举都进入显式安全状态；
- `<0.70` 必须路由人工复核；
- API 失败不得回退演示数据；
- Figma 状态清单与 ViewModel 状态清单逐项对照；
- 截图验收使用同一视口、同一夹具和同一状态，而不是只比较空壳布局。

## 7. 本轮已发现并处理的漂移

1. `docs/AGENT_EXPERIENCE_SPEC.md` 的旧示例未覆盖 Step 的 `waiting_approval`、`cancelled` 和当前完整审批类型；现已与运行时 Schema 和前端类型对齐。
2. 后端审批状态允许 `cancelled`，前端旧 Adapter 会把它回退为 `pending`；现已补齐类型、映射和回归测试，避免已取消审批被重新呈现为待处理。
3. 后端稳定键 `fatal` 在部分旧界面被直译为“致命”；统一改为“阻断项”，业务键不变。
4. 部分演示数据使用页面专用状态（如 `critical`、`review`）；这些只允许存在于页面 ViewModel，必须由 Adapter 明确映射回领域键。
5. 来源字段同时存在 `document/source_document/sourceDocument` 等历史形式；只允许 Adapter 接受这些别名，组件统一消费 `AgentSourceRef`。
