# 安全设计与威胁模型

## 1. 信任边界

浏览器、请求头、上传文件、文件名、压缩包、文档文本、解析器输出和 AI 输出均不可信。API 是授权边界，Worker 不直接接受用户网络请求。PostgreSQL 保存结构化事实与审计，StorageAdapter 保存文件，Redis 数据可重建。生产凭证来自 secret manager，不进入代码、`.env.example`、Prompt、日志或审计正文。

## 2. 身份、租户与最小权限

生产 tenant/user/roles 来自服务端认证；任何客户端 tenant_id 不能作为授权。Repository 查询和外键解析强制 tenant scope；项目成员与 admin/bid_manager/reviewer/legal/finance/viewer 权限在 service 层检查。敏感 EvidenceAsset 限制预览和下载，下载同样审计。演示可信请求头只允许 `APP_ENV=development` 的本地开发，不能部署到公网或其他服务环境。

## 3. 上传、解析和对象存储

- 消毒文件名，拒绝绝对路径、`..`、控制字符、双扩展欺骗和保留名。
- 结合扩展名、声明 MIME 和 magic bytes；应用层在读取后、持久化前限制单文件大小并先隔离后扫描。反向代理或 ASGI server 必须另设总请求体限额，避免 multipart 解析阶段占用临时磁盘或网络资源。
- ZIP 限制文件数、递归深度、压缩比和展开总量，防 Zip Slip/Bomb。
- 不执行宏、脚本、嵌入对象、外链、二维码或文档指令。
- 对象键使用 UUID，不使用原始路径；下载 URL 短期签名并绑定授权。

## 4. AI 与数据泄漏

模型无网络、数据库写入、删除、CA、付款或提交工具。文档内容以数据边界传入，Prompt Injection 只作为风险信号记录。输出经 Pydantic、页码/原文、租户和规则验证。真实 Provider 前执行敏感字段脱敏并取得凭证授权；默认 Mock。低于0.70强制复核，AI匹配不能自动 accepted。

## 5. 合规、公告和人工覆盖

金额、日期、数量、证照和包哈希由确定性规则执行。人工覆盖必须有 reviewer 权限、非空原因和前后值审计。公告变更保留旧/新版本；requires_reapproval 不能被模型取消。豁免不能删除原 fail，只能增加带 actor/reason 的决定。

## 6. 封装安全

PackageItem 归档路径重新生成并拒绝路径穿越、重复名和软链接。构建时限制总字节数，逐文件 SHA256，manifest 不包含自身且按归档路径稳定排序。ZIP 生成不等于批准：缺高风险文件时不能 ready；审批和下载分离并各自审计。系统不解锁加密 PDF、不自动签章、不调用 CA、不付款、不绕过验证码、不对外提交。

## 7. API、Web 与基础设施

输入 Schema 限长、参数化 SQL；认证、上传、解析、模型、导出分别限流。Web 使用 CSRF/同源策略、CSP、安全 Cookie、输出转义、依赖扫描。生产使用 TLS、固定镜像摘要、非 root、最小网络权限、数据库/对象存储备份恢复和生命周期策略。Compose 密码仅限隔离本机，部署前必须替换。

## 8. 审计与事件响应

记录上传、解析、模型、人工决定、证据接受/拒绝、规则、冲突、公告、任务、封装、审批、下载和导出。事件含 request_id、actor、实体、前后哈希和版本，不含密钥/token/不必要正文。审计失败时高风险写入失败关闭。跨租户访问、批量下载、恶意上传、反复模型错误和审计失败应告警。

## 9. 发布安全门禁

`make verify` 必须通过；仓库不得包含 `.env`、密钥、数据库、上传目录、构建产物或生产材料。`safety_boundaries` oracle 中 CA、付款、验证码绕过、无人提交和法律资格自动裁定必须永远为 false。
