# 标证通界面蓝图 V3

## 1. 目标

标证通保持“项目、要求、证据、编制、交付、审计”的产品框架。竞品只提供成熟的视觉和交互模式，不改变 BidEvidence 的业务状态、人工门禁和来源追溯规则。

首要体验目标：用户进入项目后，能在 30 秒内识别截止时间、最高风险、待处理事项和下一步操作。

## 2. 对标分工

| 页面或能力 | 主对标 | 复用内容 |
| --- | --- | --- |
| 全局壳层、项目目录 | GovDash | 白色侧栏、克制蓝色选中态、四项摘要、筛选条、整表布局 |
| 项目协作、任务与材料库 | Loopio | 我的任务、负责人、复核状态、内容新鲜度、项目内容回流 |
| 合规审阅 | GovDash | 目录、要求矩阵、来源原文联动 |
| 标书编制 | AutogenAI | 章节目录、正文、来源与审阅同屏 |
| Agent 业务层 | Responsive | 目标、进度、阻塞、人工门禁、产出入口 |
| Agent 技术层 | Navo、Langfuse | Run、Step、Trace、模型与错误详情 |
| 三栏和来源查看 | Glint、Aletheia | 可调整面板、页码跳转、多格式预览 |

## 3. 信息架构

### 全局导航

1. 工作台
2. 投标项目
3. 企业材料库
4. 全局任务
5. Agent 运行

审计记录保留在“智能与审计”分组中。帮助和用户操作放到底部或用户菜单，不重复显示 Agent 状态卡。

### 项目导航

项目内入口收敛为五个工作区，现有子路由继续保留：

1. 项目总览
2. 合规审阅：要求、否决项、证据匹配、一致性、补充公告
3. 标书编制：要求与响应、正文、来源、审阅
4. 整改交付：整改任务、文件封装、最终复核
5. 项目记录：项目审计和运行历史

## 4. 页面模板

### 目录页

页头与唯一主操作 → 四项以内业务摘要 → 搜索和筛选 → 数据表格 → 详情抽屉。

默认使用表格；只有任务页面需要表格和看板切换。筛选、查看详情、主操作必须真实可用。

### 合规审阅页

章节目录（220–280px）→ 要求或问题列表（360–520px）→ 原文、证据和人工操作（剩余宽度）。桌面支持拖动调整；窄屏按“列表 → 详情”顺序切换。

### 编制页

章节目录 → 正文编辑器 → 要求、证据、审阅意见和版本记录。重要结论必须能回到来源文件和页码。

### Agent 页

默认业务层只展示目标、当前步骤、进度、阻塞、待人工处理和产出。模型、Prompt、Token、耗时和错误放入技术详情。

## 5. 视觉规则

- 白色内容面与中性浅灰画布；不使用渐变、玻璃效果和装饰背景。
- 侧栏 224px，顶栏 60–64px，页面内边距 24–28px。
- 正文 14px，表格 12–13px，辅助信息不低于 11px。
- 主按钮、当前选中和链接使用单一蓝色；青绿色保留给证据可信和品牌辅助表达。
- 状态颜色只表达风险、警告、通过和人工复核。
- 卡片圆角 8–12px，控件圆角 7–9px；表格依靠边框和行背景分层。
- 动效仅用于抽屉、面板和状态变化，持续 150–200ms，并尊重减少动态效果设置。

## 6. 复用边界

- BidEvidence 保留全部业务类型、路由、API、状态机和审计规则。
- Navo 可适配壳层、命令面板、证据目录和 Run Inspector。
- Glint 只迁移可调整分栏的交互模式。
- Aletheia 的代码在明确许可证/版权边界前只参考交互和数据接口。
- GovDash、Loopio、Responsive、AutogenAI 只参考公开视觉与工作流，不复制品牌资产、私有代码和产品文案。

## 7. 交付顺序

1. AppShell 与项目目录样板。
2. 合规审阅三栏样板。
3. 企业材料库与标书编制样板。
4. Agent 业务层和技术层。
5. 迁移剩余页面并执行同视口视觉验收。
