## 1. 用户确认

用户确认本项目的规划、产品问题定义、竞品研究、UI/交互方向、实现、测试和封装基本均由本人完成。

公开表达必须既突出个人主导，也保留 AI 协作事实。推荐语义：

> 这是我的个人主导作品。我从问题定义与竞品研究开始，完成了产品规划、核心工作流、界面与交互收敛、前后端实现、合成数据、测试验收和作品封装。AI 工具用于加速调研、实现和复审；产品取舍、能力边界、最终判断与交付验收由我负责。

不得写成：

- “全程没有使用 AI”；
- “全部代码逐行手写”；
- “真实客户项目”；
- “已上线并产生真实业务指标”；
- 无法由仓库或用户确认的团队、周期、客户、模型成绩。

## 2. 参考 `block/buzz` 的结构原则

只参考 GitHub README 的展示节奏，不复制品牌、文案或产品能力：

1. 项目名 + 一句自然语言定位。
2. 少量顶层链接，避免 badge 和按钮堆叠。
3. 一张强主图，不做多元素拼贴。
4. “它到底是什么”先用业务语言讲清楚。
5. “用户能完成什么”使用具体任务，而不是功能名词堆砌。
6. 用真实小故事或失败案例证明产品判断。
7. 清楚区分“现在可用 / 尚未完整 / 明确不做”。
8. 快速开始按读者目的组织。
9. 架构保持简洁，详细内容链接到文档。
10. 用“What it is not / 它不是什么”收束边界。

风格要求：

- 克制、工程化、像真实开源项目；
- 不使用营销 Hero、渐变、徽章墙、emoji 墙、指标卡、AI buzzword 或模板化口号；
- 不把“Agent”“多智能体”“自主”放在首屏；
- 中文优先，术语自然，不写求职信腔。
