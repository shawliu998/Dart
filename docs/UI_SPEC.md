# UI 与交互规范

## 1. 信息架构和视觉

桌面优先（1280–1920px）。全局导航：工作台、项目、企业材料库、任务中心、审计中心、规则管理、系统设置；项目导航：总览、招标要求、否决项、证据匹配、一致性、补充公告、整改、封装、审计。

深蓝/蓝绿色主色、浅灰背景、白卡片。致命/高/中/低风险为深红/红/橙/黄，通过为绿、人工复核为蓝、未分析为灰。状态必须同时使用文字和图标，颜色不是唯一信息。对比度达到 WCAG AA，焦点环可见。

## 2. 项目与要求

- `/projects`：统计、搜索、阶段/风险/截止/负责人筛选和项目表格。
- `/projects/new`：基本信息、主文件、附件/公告、主体/材料范围、确认；每个上传项展示类型、大小、哈希、页数和解析状态。
- `/projects/{id}/overview`：解析 → 要求 → 证据 → 合规 → 整改 → 封装 → 提交准备；优先显示阻塞和截止。
- `/projects/{id}/requirements`：文档/矩阵/详情三栏；行选择驱动准确页码和 bbox 高亮；支持筛选、固定表头、键盘导航。人工覆盖要求原因。
- `/projects/{id}/disqualifications`：区分 AI候选、规则命中、人工确认、驳回、已解决，红色不等于法律裁定。

## 3. 材料库与证据匹配

`/evidence` 按文件夹、类型、主体、敏感级别、状态和有效期筛选。详情显示预览、Claims、来源、有效期、冲突、使用项目、版本和审计；到期/未验证/缺主体有文字提醒。

`/projects/{id}/evidence-matching` 左侧要求、右侧候选证据。显示分数、理由、主体、有效期、完整性和原文；一对多/多对一。接受和拒绝是显式人工动作，拒绝可填原因，不能“批量自动接受高分”。

## 4. 合规与一致性

要求详情“判断”展示 result、expected、actual、rule code/version、reason、sources 和是否复核。人工覆盖弹窗必须有原因并提示将写入审计。

`/projects/{id}/consistency` 以字段、值、文件、风险、建议值、状态为主列表；详情并排显示每个 `filename:page`。支持采用标准值、合理差异和创建任务，禁止无原因隐藏冲突。

## 5. 补充公告与整改

`/projects/{id}/amendments` 左右展示旧/新条款，中间显示增删改、影响级别和对象。每个变化列出受影响要求、证据、任务、报价、封装项和重新审批标记。应用变化与重跑检查是独立动作。

`/projects/{id}/tasks` 提供表格和 Kanban，按负责人/优先级/来源/截止筛选。任务详情必须可回到具体来源，显示建议步骤、附件、评论、完成证明、复核和审计。

## 6. 文件封装与审计

`/projects/{id}/package` 左侧文件树，中间校验，右侧预览/来源。检查存在、版本、命名、格式、大小、缺页、签章候选、日期、主体、修订、加密、可打开和重复。生成 ZIP 前显示所有 fail/warning；缺少授权书时可生成预览但不能自动 ready/approved。审批和下载分开。

`/projects/{id}/audit` 为只读时间线/表格，按 actor/Agent/action/entity/time/risk/model/prompt 筛选，展示前后值、哈希、规则/模型和人工原因。

## 7. 通用状态和无障碍

每个异步区域实现 Skeleton、空状态、失败、重试和真实进度。Toast 不是唯一错误载体。危险操作要求确认；高风险动作要求理由。全部功能可键盘操作，图标按钮有 accessible name，表单错误关联字段。平板支持只读/简单复核；手机只支持提醒、任务和审批。

## 8. 固定免责声明

要求、否决、证据、合规和封装页面必须可见：AI 结果用于辅助审查，不构成法律意见、招标代理意见或最终资格判断。最终结论应由授权人员复核。
