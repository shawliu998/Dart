# 中英文界面切换执行 Brief

## 竞品依据

参考成熟工作流产品常见的账户级语言切换方式：语言选择放在现有用户菜单中，切换后保持当前路由、项目和编辑状态。视觉继续复用现有 Dart 壳层，不引入新的品牌或页面结构。

## 用户任务

招聘评审或项目使用者可以：

1. 默认以英文打开 BidEvidence；
2. 在用户菜单中切换为中文；
3. 刷新或重新打开页面后保留语言选择；
4. 在两种语言下完成同一条七步投标工作流；
5. 始终看到原始中文招标文件名、条款原文、证据摘录和企业数据。

## 当前差距

- 当前没有 locale provider、翻译字典或语言持久化。
- `frontend` 中约 50 个 TS/TSX 文件包含中文文案。
- AppShell、反馈组件和七步核心工作台的界面文字直接写在组件内。
- `<html lang>` 固定为 `zh-CN`。

## 可见结果

- 默认语言为 English。
- 用户菜单提供 `English / 中文` 控件并显示当前选择。
- 导航、按钮、状态、空态、错误提示和核心工作台标签随语言切换。
- URL、项目选择、表单内容和业务数据不因语言切换而重置。
- 招标原文、证据和合成企业/项目数据保持中文。

## 验收证据

- 英文默认状态截图。
- 同一路由切换中文后的截图。
- 刷新后语言选择仍然生效。
- 390px 下语言控件可用且无水平溢出。
- locale provider、AppShell 切换和至少七步核心页面的双语测试通过。
- `lint`、`typecheck`、核心组件测试和 production build 通过。

## 复用决定

- 复用 `frontend/components/layout/app-shell.tsx` 的用户菜单，不新增设置页或英文路由。
- 复用所有现有工作台、API、DTO、状态与 fixture；仅把界面文案替换为 locale key。
- 新增一个轻量 locale 模块是必要的缺失层，用于字典、provider、持久化和翻译函数。
- 不新增 `V2`、replacement、平行页面或第二套导航。
- 不翻译服务器返回的文件名、条款原文、证据摘录、项目名、企业名和人工输入。
