# 个人贡献与 AI 协作说明

## 作品性质

BidEvidence 是我的个人主导作品。它不是客户委托项目，也不代表已经上线的商业系统；当前业务数据、故障样本和验收数字均来自仓库内可重复生成的合成 fixtures。

## 我完成的主要工作

### 问题与产品规划

- 把“AI 写投标书”重新定义为“证据约束下的正式承诺工作流”。
- 拆解文件接收、要求审阅、企业材料、响应编制、整改、交付和终审七个阶段。
- 确定模型、规则与人工三方责任边界。
- 控制范围，不把聊天、Agent、审计或运行环境当作核心产品卖点。

### 竞品研究与设计

- 审阅 GovDash、Loopio、Responsive、MyPitchFlow 等公开流程或受控体验。
- 选择单一任务结构作为各核心页面参考，避免混杂多套视觉语言。
- 规划信息架构、页面层级、状态语义、移动重排和真实回跳路径。
- 通过 production 截图与自动化证据完成逐批验收。

### 工程实现

- Next.js、TypeScript 前端工作台与交互状态。
- FastAPI、Pydantic、SQLAlchemy 领域服务与 API。
- 文档来源、Evidence Claim、响应、整改、交付包和复核数据契约。
- 金额、日期、数量、主体、有效期、一致性、文件与哈希的确定性规则。
- 合成 PDF/DOCX/XLSX、固定 oracle、种子数据与演示链路。

### 测试与交付

- 单元、组件、API、E2E、production build 和独立验收。
- Batch 01–05 产品/技术双钥匙复审。
- README、案例复盘、架构、测试证据、截图和最终 ZIP 封装。

## AI 工具参与了什么

AI 工具用于：

- 加速公开资料整理和方案比较；
- 辅助生成或修改部分代码；
- 执行重复性检查和测试；
- 以 Orchestrator / Reviewer 角色提出问题并复审证据。

AI 工具没有替我完成以下责任：

- 决定产品问题和最终范围；
- 选择竞品参考与页面取舍；
- 决定模型、规则和人工的责任边界；
- 接受业务证据、批准响应或作出合规结论；
- 对仓库路径、接口、测试和最终交付作技术验收。

## 对外表述边界

可以表述为：

> 我个人主导并完成了 BidEvidence 的问题定义、产品规划、核心工作流、主要界面与交互、前后端实现、合成数据、测试验收和作品封装。AI 工具参与调研、实现与复审；产品取舍、工程判断和最终验收由我负责。

不使用：

- “完全没有使用 AI”；
- “每一行代码均由本人手写”；
- “真实客户项目”；
- “已经产生商业收益或效率提升”；
- 没有原始报告支撑的真实模型准确率、成本或延迟。
