# GitHub 展示最终复审 Brief

## 角色与目标

你是本轮 GitHub 展示的 Orchestrator / Reviewer。Codex 已按上一轮决策完成 README、个人贡献说明、案例文档补充和桌面/移动端预览。请只做最终复审，不重新设计产品，也不提出与仓库展示无关的新功能。

参考目标是 `block/buzz` 的克制表达方式：标题、单句定位、单张产品主图、具体任务、诚实边界、运行方式与架构。不要照搬其文案或产品内容。

## 需要检查

1. README 是否保持单一视觉主线，且只有 7 个二级标题。
2. 标题、单句定位、单张 Hero 和首屏信息是否清楚。
3. “个人主导”是否足够明确、可信且不夸大。
4. AI 协作是否只作为方法说明，没有成为主卖点。
5. 是否仍有模板化、营销化、AI 味或元素堆叠。
6. 所有能力、测试和验收表述是否有仓库证据支撑。
7. GitHub About、topics、social preview 与默认分支检查项是否一致。
8. 桌面和移动端预览是否存在明显排版问题。

## 输出格式

- 先给结论：`README_ACCEPT` 或 `README_REVISE`。
- 按 P0 / P1 / P2 列出问题；没有则明确写“无”。
- P0 / P1 必须给出精确到文件与段落的最小修改。
- P2 只记录建议，不阻塞本轮封装。
- 如果没有 P0 / P1，请明确写：

```text
README_ACCEPT
无 P0 / P1，可进入最终 R4 封装。
```
