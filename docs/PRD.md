# 产品需求文档（PRD）

## 1. 产品目标

标证通 BidEvidence 是中文招投标合规与交付工作台。它把招标文件转换成可执行的合规矩阵，使每项响应都能回到招标原文、企业证据、确定性规则、责任人和审计记录。主界面是项目、矩阵、文档、材料、风险、任务和封装，不是聊天框。

核心原则：先证据后结论；LLM 负责理解、代码负责计算；低置信度转人工；任何外部影响操作都需授权人员批准。

## 2. 用户与权限

| 角色 | 主要任务 | 关键权限 |
|---|---|---|
| `admin` | 租户、成员、策略和规则 | 组织级管理，不绕过项目审计 |
| `bid_manager` | 建项目、分配任务、组织封装 | 项目写入、封装申请 |
| `reviewer` | 确认要求、证据、否决项和覆盖 | 复核、审批、填写原因 |
| `subject_matter_expert` | 处理技术要求 | 指定要求与任务写入 |
| `legal` / `finance` | 法务、主体、报价复核 | 受限材料访问与专业复核 |
| `viewer` | 查看矩阵、来源和审计 | 只读，不可审批或下载敏感材料 |

## 3. 完整 MVP 范围

1. 创建项目，上传招标主文件、附件、补充公告和投标工作文件。
2. 文件安全校验、SHA256 去重、页码级解析、OCR fallback 接口和进度任务。
3. 结构化要求与否决项候选，逐条来源跳页和人工确认。
4. 企业材料库、EvidenceClaim、有效期/主体检查、证据推荐及人工接受/拒绝。
5. 确定性合规规则，展示 expected、actual、rule、reason 和 sources；人工覆盖必须有原因。
6. 项目级事实归一和跨文件一致性问题，支持采用标准值、合理差异和整改任务。
7. 补充公告前后差异、受影响要求/证据/任务/封装项和重新审批。
8. 来源驱动的整改任务，负责人、复核人、截止时间、状态和解决证明。
9. 最终文件树、缺件/命名/格式/大小/版本/修订/签章候选检查，生成预览与 ZIP/SHA256 manifest。
10. 上传、模型、人工决定、规则、任务、封装、审批和下载的追加式审计。

演示闭环：

```text
上传与解析 → 24条要求 → 3条否决候选 → 7份企业证据/17个Claim
→ 证据匹配 → 14项确定性合规检查 → 7项一致性问题
→ 3项补充公告变更 → 7个整改任务 → 9项封装树
→ ZIP + SHA256 manifest → 人工审批守门 → 审计导出
```

## 4. 明确禁止和不做

- 不自动支付保证金、操作 CA/数字证书、绕过验证码或无人值守提交。
- 不自动作出法律资格、是否废标或保证中标的最终裁定。
- 不让 LLM 计算金额、日期、数量或最终规则结果。
- 不执行上传文档中的指令，不允许模型删除文件或自动接受证据。
- 不实现复杂工程造价、施工组织设计自动生成或真实外部消息发送。

## 5. 功能验收

### 项目与文档

项目 CRUD、租户隔离和软删除可测试；上传拒绝路径穿越、MIME 不符和超限文件；解析任务可轮询、失败可重试、重复文件幂等。每条要求含文件、页码、条款、原文、置信度和复核状态。

### 证据与合规

材料按主体、类型、状态、敏感级别和有效期筛选；一份材料可产生多个 Claim。推荐匹配默认 `suggested/needs_review`，只有人工动作可进入 `accepted`。规则输出 PASS/FAIL/WARNING/MANUAL_REVIEW，并且金额/日期/计数结果不来自模型。

### 冲突、公告和任务

一致性问题并排展示每个值和 `filename:page`；处理原因进入审计。公告展示修改前后原文及影响对象，不只给摘要；受影响内容需重新审批。每个任务必须引用合规检查、冲突、公告变更或封装校验之一。

### 封装与审计

封装检查在生成前显示全部失败和警告。可生成预览 ZIP 和 UTF-8 SHA256 manifest，但存在高风险缺件时不得自动标记 ready/approved。审批和下载为两个独立审计动作；审计事件不可普通更新或删除。

## 6. 演示验收基线

`demo/expected_results/expected_results.json` 是版本 2.0 oracle，固定时间锚点为 2026-07-16，评估日为 2026-07-30。它必须保留：1 张过期证书、主体名称冲突、两种报价冲突、缺证据、案例缺验收、负责人年限不足、公告延期/技术修改/新增资质、授权书缺失、错误文件名和修订记录。

守门目标：金额/日期计算错误、不存在页码、无证据正式结论、低置信度自动通过、未授权外部提交均为 0。

## 7. 非功能要求

- 常规 API P95 小于 500ms（不含解析/模型）；项目列表首次加载目标小于 2 秒。
- 200 条要求的矩阵保持流畅；后台任务可观察、幂等和可重试。
- WCAG AA，状态不只依赖颜色，表格/对话框可键盘操作。
- 空库迁移、seed 幂等、Mock 离线演示、lint/type/unit/integration/E2E/build 全部通过。

## 8. 发布判定

只有 `make verify` 全绿，且无真实密钥、用户上传、数据库、构建产物进入 Git，才可交付。未实现的外部集成必须作为已知限制显示，不能做无行为按钮。
